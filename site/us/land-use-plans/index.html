Confidence

No single official nationwide zoning dataset was found: zoning is adopted locally. Two tested cities publish open polygon services: Denver (3,934 polygons; ordinance number/year and code version per polygon) and Austin (22,503 polygons; ordinance boundaries in a separate layer, linked only by spatial overlay). Nationwide coverage appears only as a paid commercial layer (Regrid) or a nonprofit viewer (National Zoning Atlas); neither was verified here. Zone codes are not comparable between places; future-land-use plans are separate layers.

Confidence reason: Denver and Austin services were queried live; the national picture rests on two web pages (NZA, Regrid) and failed attempts to read federal and aggregator catalogues.

Local search terms

  • zoning / zone district — Locally adopted land-use regulation dividing land into districts
  • rezoning ordinance — Council ordinance that changes a zoning map, often tied to a case number
  • PUD (Planned Unit Development) — Site-specific zoning with its own approved document (Denver PUD_DOCUMENT)
  • Former Chapter 59 — Denver's pre-2010 zoning code still governing some properties
  • Future Land Use Map (FLUM) — Planned land use recommendation; not current zoning
  • Land Development Code — Austin's Title 25 code defining zoning districts

Main caveats

  • Zoning is local: each city/county defines its own districts, so a code such as 'SF-3' or 'U-SU-A' only has meaning in its own code.
  • Only Denver and Austin were tested; thousands of other US jurisdictions were not checked and may publish nothing, a viewer or an image.
  • Denver mixes two codes in one layer: Denver Zoning Code (2010) and Former Chapter 59 (1956), shown by ZCODE_VERSION.
  • Austin links a polygon to ordinances only by overlay; one point can fall in several ordinance polygons, one being a 1999 citywide code ordinance.
  • Both cities state the data is informational, not for legal/engineering determinations; adopted ordinances and maps prevail.

City and County of Denver, Community Planning and Development / Geospatial Denver · Official · ArcGIS REST FeatureServer (query JSON/GeoJSON; service lists csv, shapefile, geoPackage, filegdb, kml, excel exports) · API · License: Custom terms in the ArcGIS item: ACCESS CONSTRAINTS: None; provided AS IS; NOT FOR ENGINEERING PURPOSES

Example request

curl -G 'https://services1.arcgis.com/zdB7qR0BtYrg0Xpl/ArcGIS/rest/services/CCD_Zoning/FeatureServer/27/query' --data-urlencode 'geometry=-104.9847,39.7392' --data-urlencode 'geometryType=esriGeometryPoint' --data-urlencode 'inSR=4326' --data-urlencode 'spatialRel=esriSpatialRelIntersects' --data-urlencode 'outFields=ZONE_DISTRICT,ZONE_DESCRIPTION,ZONE_DIST_TYPE,ORD_NUM,ORD_YEAR,ZCODE_VERSION' --data-urlencode 'returnGeometry=false' --data-urlencode 'f=json'

Example result

One feature: ZONE_DISTRICT D-CV, ZONE_DESCRIPTION 'Downtown - Civic (D-CV)', ZONE_DIST_TYPE 'Commercial Mixed Use', ORD_NUM 333, ORD_YEAR 2010, ZCODE_VERSION 2010 (queried 2026-11-20).
